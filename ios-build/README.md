# OmniTaps — local iOS / macOS test builds

Standalone wrappers that embed the built Vite app (`dist/`) into a native shell.
Distribution is **local only**: ad-hoc / development signing, no App Store, no
notarization, no uploads.

## Layout

```
ios-build/
  stage-web.sh            copies dist/ -> build/www and makes it bundle-safe
  build-macos.sh          builds + ad-hoc signs build/macOS/OmniTaps.app
  package-macos.sh        ditto-archives the .app -> dist/ + SHA-256
  build-ios.sh            simulator / device / unsigned builds
  shared/WebBundle.swift  custom URL scheme handler used by BOTH targets
  macOS/main.swift        AppKit window + WKWebView
  macOS/Info.plist        bundle metadata
  macOS/Entitlements.plist   intentionally empty (see below)
  macOS/AppIcon.icns      generated from dist/icon-512.png
  ios/OMNITapsKit/        AppDelegate.swift, Info.plist, Entitlements.plist
  ios/project.yml         XcodeGen spec (www/ added as a folder reference)
  ios/OmniTaps.xcodeproj  generated by XcodeGen, not committed
  tools/xcodegen/         optional local XcodeGen (only if brew is unavailable)
  build/                  generated output (gitignored)
```

## Why a custom URL scheme and not `file://`

`file://` cannot host this app. WebKit refuses to load **ES modules** from a
file origin (opaque origin → CORS failure), and the app uses `BrowserRouter`,
which needs a real origin for the History API. `shared/WebBundle.swift` serves
the bundle over `omnitaps://local/`, which fixes module loading, `pushState` and
web storage in one place, and removes any hardcoded absolute path.

`stage-web.sh` also rewrites Vite's absolute `href="/assets/…"` to relative and
strips `crossorigin`; the same staged `build/www` is used by both targets.

## Build and run — macOS

```bash
cd ios-build
./build-macos.sh
open build/macOS/OmniTaps.app
```

Universal (`x86_64` + `arm64`), deployment target macOS 12, ad-hoc signed.

## Package for local download (macOS)

```bash
cd ios-build
./package-macos.sh      # -> dist/OmniTaps-macOS.zip + dist/SHA256SUMS
```

`ditto -c -k --sequesterRsrc --keepParent` is used rather than `zip` so
symlinks, extended attributes and the `OmniTaps.app` wrapper survive. The script
re-verifies the signature, extracts the archive into a temp directory and
verifies the extracted bundle again (and prints its `lipo -archs`) before it
writes `dist/SHA256SUMS`.

### What the tester must do

The archive is ad-hoc signed and **not notarized**, so macOS quarantines the
download and Gatekeeper refuses the first open. That is expected, not a broken
build.

1. Verify the download:

   ```bash
   shasum -a 256 -c SHA256SUMS
   ```

2. Unzip with Archive Utility (double-click) or `ditto -x -k OmniTaps-macOS.zip .`.
   Both preserve bundle metadata; a bare `unzip` can drop resource forks.
3. Move `OmniTaps.app` where you like (`/Applications` is fine).
4. Unblock the first launch once, with any of:
   - **Control-click** (right-click) `OmniTaps.app` → **Open** → **Open** again, or
   - **System Settings → Privacy & Security → Open Anyway**, or
   - `xattr -dr com.apple.quarantine /Applications/OmniTaps.app`

   macOS words the block as *"Apple could not verify “OmniTaps” is free of
   malware"* (macOS 15+) or *"cannot be opened because the developer cannot be
   verified"* (older releases).
5. Expected assessment: `spctl --assess --type execute -vvv OmniTaps.app`
   prints `OmniTaps.app: rejected` and exits `3` (older releases add
   `source=no usable signature`). That is Gatekeeper declining to vouch for an
   ad-hoc, non-notarized build — not a build failure. The integrity check that
   does apply is `codesign --verify --strict`, which passes on the extracted
   copy and still passes after the quarantine attribute is removed.

## Build and run — iOS Simulator

Requires Xcode with an iOS runtime. No signing identity is used.

```bash
cd ios-build
./build-ios.sh simulator        # build, install, launch, wait for settle, screenshot
SKIP_RUN=1 ./build-ios.sh simulator   # build only
SIM_UDID=<udid> ./build-ios.sh simulator
```

The script generates `ios/OmniTaps.xcodeproj` with XcodeGen, builds with
`-sdk iphonesimulator CODE_SIGNING_ALLOWED=NO`, installs into the first available
iPhone simulator, launches it, and waits for the SPA to **settle**.

The probe is gated, not sampled at `didFinish`: `didFinish` fires before React
mounts and the app plays a short "network boot" intro, so an early sample
reports a loading screen. The debug probe polls every 0.4 s and only reports
once `#root` has children, the visible text is at least 250 characters, and the
same text repeats for three samples. Any of the boot markers
(`Connecting your`, `NETWORK BOOT`, `Loading…`) disqualifies a sample, and the
script fails the run if the settled text still contains them.

A clean run prints and saves:

```
probe: {"url":"omnitaps://local/demo","rootChildren":1,"textLength":3841,
  "text":"Skip to content Omnitaps OMNITAPS · ALL-IN-ONE SYSTEM FOR HOSPITALITY & RETAIL
   One company. One system. Every part of your business. …",
  "storage":"ok","pushState":"ok"}
```

- `build/ios/render-probe.json` — the probe payload (`text` is capped at 600
  characters so the `storage`/`pushState` keys survive unified-log truncation;
  `textLength` reports the full length).
- `build/ios/ios-simulator-home.png` — simulator screenshot taken right after
  the probe settles, so the rendered Home UI is evidenced by eye too.

The script exits non-zero if the probe is missing, empty, boot-screen text, or
an error page. Read the probe manually with:

```bash
xcrun simctl spawn <udid> log show --last 5m --style compact \
  --predicate 'eventMessage CONTAINS "OMNITAPS_SMOKE"'
```

The probe lives behind `#if DEBUG`, so release/device builds do not log it.

## Tester diagnostics (iOS)

Device installs cannot be debugged by attaching to them, so the shell records
what went wrong on the device itself and gives the tester a way to hand it back.

**Captured** (via `Diagnostics.swift`):

- `js-error` — `window.onerror` in the capture phase, including source URL,
  line/column and the stack.
- `unhandled-rejection` — `unhandledrejection`, with the reason or its stack.
- `console-error` — `console.error` output, budgeted to 40 entries per page load
  so a render loop cannot flood the file.
- `resource-error` — failed images/scripts/stylesheets (`error` on the element).
- `navigation-failed` — `didFail` / `didFailProvisionalNavigation`, with the
  **attempted** URL (captured in `decidePolicyFor`, since `webView.url` still
  points at the previous page), the message, domain and code.
- `web-process-terminated` — `webViewWebContentProcessDidTerminate`, the silent
  white-screen failure. The shell logs it and reloads (up to three attempts).
- `render-stalled` — Debug only: the settle probe gave up without real content.
- `session` — app version/build, iOS version, device model and start URL.

The JS bridge is injected as a `WKUserScript` at **document start**, so errors
thrown while the app is still booting are captured too.

**Where it lives:** `Library/Application Support/OmniTaps/diagnostics.log` in the
app container. It rotates at 256 KB into `diagnostics.log.1` (one backup), so it
cannot grow without bound. The exact path is shown at the top of the diagnostics
screen.

**How a tester gets it out:** tap the small ⓘ bubble in the bottom-right corner
of the app (it is 38 pt and low-contrast so it does not cover the web UI). The
sheet shows the full log with:

- **Copy** — puts the whole log on the clipboard.
- **Share** — system share sheet (AirDrop, Mail, Files, Notes…).
- **Clear** — deletes the log and its backup.

### Automation hooks (Debug builds)

Every diagnostics path can be exercised without hand-tapping. Launch the app
with one of these arguments:

| Argument | What it does |
| --- | --- |
| `-OmniTapsDiagnosticsSelfTest YES` | Throws a real JS error and an unhandled rejection after the page settles. |
| `-OmniTapsDiagnosticsUITest YES` | Taps the ⓘ bubble, fires the real Copy / Share / Clear bar-button targets, and logs `[OMNITAPS_DIAG_UI]` with `copyChars`, `sharePresented`, `popoverAnchor` and `clearEmptied`. Check the clipboard with `simctl pbpaste`. |
| `-OmniTapsBadNavigation YES` | Loads `omnitaps://local/assets`, a bundle path the scheme handler cannot read, so `didFailWithError` surfaces as a real navigation failure. |
| `-OmniTapsDeepLink YES` | Starts on `omnitaps://local/demo` to prove the SPA fallback still serves client-side routes. |

```bash
UDID=$(xcrun simctl list devices booted -j | python3 -c 'import json,sys;print(list(json.load(sys.stdin)["devices"].values())[0][0]["udid"])')
xcrun simctl launch $UDID com.onouh.omnitaps -OmniTapsDiagnosticsUITest YES
xcrun simctl pbpaste $UDID | head          # the text Copy put on the pasteboard
xcrun simctl get_app_container $UDID com.onouh.omnitaps data   # diagnostics.log lives here
```

### Missing assets return 404

The scheme handler only answers **extensionless** paths with `index.html` (that
is what keeps `BrowserRouter` routes like `/demo` working). A request for a
missing file — such as the `/_vercel/insights/script.js` beacon the web app still
registers — now receives a real `404 Not Found` instead of HTML, so it no longer
produces a bogus `SyntaxError` in the diagnostics log. Those two requests are
still recorded as `resource-error` lines, which is accurate: the files really are
absent.

### XcodeGen

`build-ios.sh` uses `xcodegen` from `PATH`, falling back to
`ios-build/tools/xcodegen/bin/xcodegen`. To obtain it:

```bash
brew install xcodegen
# or, without Homebrew:
curl -fsSL -o /tmp/xcodegen.zip \
  https://github.com/yonaskolb/XcodeGen/releases/latest/download/xcodegen.zip
unzip -oq /tmp/xcodegen.zip -d ios-build/tools
```

## Device install

A device build **additionally requires a signing identity and a provisioning
profile** — a free Apple ID gives you a personal team, an Apple Developer
Program membership gives you more devices. The simulator never needs these.

```bash
DEVELOPMENT_TEAM=ABCDE12345 ./build-ios.sh device
```

Then install the resulting `Release-iphoneos/OmniTaps.app` with Xcode
(Window → Devices and Simulators) or `xcrun devicectl device install app`.

Without an identity you can still produce a device-ready unsigned artifact:

```bash
./build-ios.sh unsigned     # -> build/ios/OmniTaps-unsigned.ipa
```

Sign it with `codesign` and embed a provisioning profile before installing.

## Code signing (local distribution)

macOS — `Entitlements.plist` is **deliberately empty**. `get-task-allow` is a
*restricted* entitlement: an ad-hoc signature carrying it is rejected at launch
with `Code has restricted entitlements, but the validation of its code signature
failed.` App Sandbox is off because the key is absent. If you sign with an Apple
Development identity plus a provisioning profile you may re-add it for debugging.

iOS — `Entitlements.plist` contains only `get-task-allow`, required by
development-signed device installs. iOS has no App Sandbox entitlement.

## Local-install artifacts

| Artifact | Path | Signed |
| --- | --- | --- |
| macOS app | `build/macOS/OmniTaps.app` | ad-hoc (`codesign --verify --strict` clean) |
| iOS simulator app | `build/ios/Build/Products/Debug-iphonesimulator/OmniTaps.app` | unsigned by design (`CODE_SIGNING_ALLOWED=NO`) |
| iOS unsigned device IPA | `build/ios/OmniTaps-unsigned.ipa` | none — sign before installing |
| macOS download archive | `dist/OmniTaps-macOS.zip` | contains the ad-hoc signed app |
| Checksum | `dist/SHA256SUMS` | — |
| Simulator render evidence | `build/ios/ios-simulator-home.png`, `build/ios/render-probe.json` | n/a |

Reproduce all of them:

```bash
cd ios-build
./build-ios.sh simulator     # simulator app + probe + screenshot
./build-ios.sh unsigned      # device .app + .ipa (unsigned)
./build-macos.sh             # macOS .app, ad-hoc signed
./package-macos.sh           # macOS .zip for download + SHA-256
```

## Known limits of this test build

- Only the static shell is bundled. Pages that call `/api/*` or Supabase need
  network access to a running API host, which is not bundled.
- The macOS app is not notarized: a downloaded copy is quarantined and blocked
  on first open. See "What the tester must do" above — Control-click → Open, or
  `xattr -dr com.apple.quarantine`, and `spctl` reporting `rejected` is expected.
- The simulator build is `Debug`; the probe and `xcodebuild` logs are expected
  noise, not failures.
